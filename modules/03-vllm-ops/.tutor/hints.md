## 3.2 KV startup error
- H1: Read the FIRST error line in the log, not the last one. What number does the engine print for the largest length that would fit?
- H2: Four levers: length, utilization (<= 0.95), KV dtype, activation budget. Compute which combination reaches the floor.
- H3: With bf16 KV even util 0.95 cannot reach the floor on this GPU. What halves KV bytes per token?
- H4: `--kv-cache-dtype fp8 --max-model-len <floor> --gpu-memory-utilization 0.92`.

## 3.3 Eight concurrent, no preemption
- H1: Run the load, then compare `peak running` with 8 and look at what else the metrics show (waiting, KV).
- H2: Two independent limits: the sequence cap and the KV pool. Raising only the cap makes running grow until KV is the limit (and then preemption).
- H3: Needed tokens = 8 x (prompt + max_tokens); compare with the pool (`kv_cache_size_tokens` from apply.sh output). More pool = more utilization or fp8 KV.
- H4: `--gpu-memory-utilization 0.90 --max-num-seqs 16` (or any combination whose pool >= needed tokens with cap >= 8).

## 3.4 p95 by hand
- H1: Cumulative buckets: count the total, multiply by 0.95. Which bucket contains that rank?
- H2: `histogram_quantile` interpolates linearly inside the bucket: `lower + (upper-lower) x (rank - count_below) / (count_in_bucket)`.
- H3: Use the `_bucket` lines of `vllm:time_to_first_token_seconds` only; `+Inf` equals `_count`.
- H4: Walk through the numbers of the learner's own snapshot together; let them do the final division.
