## Quiz

1. Step k prompt = P + (k-1)d. Total = nP + d*n(n-1)/2. n=8: 40,000 + 1,200*28 = **73,600**. n=16: 80,000 + 1,200*120 = **224,000**. Twice the steps costs about **3.0x** the tokens (quadratic term). Hence `max_steps` and a per-run token budget; also TPM sizing must use the whole history, not the new tokens. (Prefix cache lowers GPU prefill work, not the billed/TPM-counted prompt tokens.)
2. `[..., assistant{tool_calls:[{id:A},{id:B}]}, tool{tool_call_id:A, content}, tool{tool_call_id:B, content}]`. The assistant message with its `tool_calls` must stay in history; each id answered exactly once. A strict server returns 400 (tool_calls must be followed by tool messages for each id).
3. Causes: no `--jinja` on llama.cpp (template without tool rendering); wrong/missing `--enable-auto-tool-choice --tool-call-parser` on vLLM; model chat template has no tool section; gateway/model alias pointing at a model without tool support. Check: raw `content` and server startup flags first. A weak model typically produces *valid* `tool_calls` with wrong tool/arguments (semantic error); here the structure is missing (serving error).
4. JSON-RPC error = protocol-level failure (unknown method/tool, invalid params): for client code, not the model. `isError: true` = the tool ran and reported failure: put the text in front of the model so it can correct arguments or give up gracefully.
5. stdio, Streamable HTTP (legacy HTTP+SSE deprecated). stdout *is* the protocol channel; stray text corrupts framing; log to stderr. Stateful servers keep per-session state (`Mcp-Session-Id`), a round-robin LB sends the next request to a replica without it -> unknown session; fix with sticky sessions/shared store. 2026-07-28 is stateless: requests self-contained (+ `server/discover`), any replica can serve any request.
6. (a) Command injection: `shell=True` with model-controlled `pattern`/`path` -> argv list `["grep","-r","--",pattern,path]`, no shell. (b) Unrestricted path (reads anywhere, e.g. `/etc/shadow`, secrets) -> jail to an allowed root after `realpath`, reject `..`/symlink escape. Also acceptable: no output size cap/timeout; useless one-word description "grep" (model cannot choose well).
7. Tool poisoning: hostile instructions inside a tool's description/schema that the model obeys. Rug pull: server changes tools/descriptions after being approved. Control: pin server version/digest, review and re-approve when `tools/list` changes; enforce in the MCP gateway (allow-list of server+tool, hash of the tool manifest) and the internal registry.
8. Remove egress: the agent runs with no route out except the gateway/MCP gateway; `fetch_url` becomes an allow-listed internal-wiki fetch; credentials not visible to the model/sandbox. (Air gap already removes most egress; the remaining leak paths are internal services and any tool that can write somewhere readable by the attacker, e.g. creating a public issue/comment.) Accept answers that keep the three-legs reasoning and name a concrete control.
9. `--network none`: exfiltration/payload download (connect fails "Network is unreachable"); `--read-only` + capped tmpfs: persistence/tampering/disk fill (`Read-only file system`, `No space left` at 16m); `--cap-drop ALL`: raw sockets, mount, chown (`Operation not permitted`); `--pids-limit 64`: fork bomb (`Resource temporarily unavailable`); `--memory 128m`: memory hog (killed, exit 137, OOMKilled); `--user 65534`: root-only actions (`id` shows 65534). Missing: `--security-opt no-new-privileges`, `--memory-swap` (swap == memory), `--cpus`, timeouts (in-container `timeout` + outer kill), container name/label + janitor, output cap, ulimits, image by digest.
10. With only `--memory`, Docker defaults `--memory-swap` to 2x memory when swap accounting is available -> 256m RAM + 256m swap = 512 MB. Fix `--memory-swap 256m` (equal). Confirm: exit code 137 and `docker inspect -f '{{.State.OOMKilled}}'` = true.
11. A stopped client does not stop the daemon-side container; `--rm` is executed by the client on normal exit/with the daemon on stop, but a hung/killed run leaves it (and its resources) running. Prevention: unique name + label per job, in-container `timeout`, outer watchdog (`docker kill`/`rm -f` by name in a `finally`/trap), and a janitor that reaps labelled containers older than max runtime. In k8s: `activeDeadlineSeconds` + `ttlSecondsAfterFinished`.
12. The Docker API = root on the host (start a privileged container with `/` mounted, read secrets, stop other containers). `:ro` only makes the socket *file* read-only for file operations; connecting and sending API calls still works. Example: `curl --unix-socket /var/run/docker.sock http://localhost/containers/json` (or `docker run -v /:/host --privileged ... chroot /host`).
13. First run persisted ~899 (depending on batch size) random-id points; the retry inserts all 1,000 again -> about **1,899**, duplicates in search results. Fix: deterministic ids (`uuid5` of source + chunk index + content hash) so an upsert overwrites; `wait=true`. Proof: `POST /collections/{c}/points/count {"exact":true}` equals the expected chunk count (plus a known-fact search ranks first).
14. 2.5e6 x 768 x 4 B = 7.68 GB (7.15 GiB). int8 scalar quantisation 4x smaller: 1.92 GB (1.79 GiB) for quantised vectors. Real need higher: HNSW graph links (m=16 -> ~2 x 16 x 4-8 B per point), payload, ids, segment overhead, WAL/optimizer headroom, and the original float vectors kept on disk (or RAM) for rescoring; budget ~1.5-2x.
15. Ingest: upsert returns 400 (vector dimension 768 vs collection 384). Query side: query vectors (768) cannot be searched in the 384 collection (error), or, if a same-dimension model is swapped, silently meaningless similarity (worse recall). Safe procedure: create a new collection (new dim, model name in its name), re-embed the whole corpus from the stored source/chunk manifest into it, evaluate recall on a labelled set, switch the **Qdrant collection alias** atomically (`create_alias`/`delete_alias` in one request), keep the old collection for rollback, and move the gateway alias target together with the app's query path (never change one without the other).

## Expected lab answers and common mistakes (reference: `.tutor/solution/`)
Simulation note for the learner: the "model" behind `mock-a` is scripted mock-chat (pattern -> tool_calls, then a templated answer containing the nonce of the last tool result); the embeddings are real (llama.cpp bge-small, 384 dims); the sandbox, MCP servers, Qdrant and the tripwire are real. Production: a real model with a tool-call parser (vLLM `--enable-auto-tool-choice --tool-call-parser`, llama.cpp `--jinja`); the loop/MCP/sandbox code is the same. A weak real model would add wrong-tool/wrong-argument failures that this lab cannot show.

- **7.1** (a-d): `requests.post(GATEWAY/v1/chat/completions, json={model, messages, tools})`; append the assistant message WITH its `tool_calls`, then one `tool` message per call with `tool_call_id`; `json.loads(arguments)` with errors returned as the tool result; `for _ in range(max_steps)`; `None` -> exit 2; debug output to stderr. 7.1b/c are checked on a logging proxy: roles tail `assistant, tool[, tool]`, ids equal, each result attached to its own call. Common: dropping the assistant message, using the first id for all results, answering only the first of two calls, printing tool traces to stdout, forgetting `tools` in the request (mock-chat then never calls the tool), exit 1 instead of 2.
- **7.2** (a-d): `from mcp.server.mcpserver import MCPServer` (2.x name; `FastMCP` import fails), `@app.tool()` with type hints + docstring, `app.run("streamable-http", host="127.0.0.1", port=args.port)`. Unknown tools come back as `is_error=True` in this SDK. Common: stdio transport, port ignored, `ticket_status` hard-coding a path, empty docstrings.
- **7.3** (a-i): all of `--network none --read-only --tmpfs /tmp:...size<=32m --cap-drop ALL --security-opt no-new-privileges --pids-limit 64 --memory 256m --memory-swap 256m --user 65534:65534`, `--name sbx-<rand> --label course=aiinfra`, inner `timeout -k`, outer watchdog + `trap 'docker rm -f'`, exit 124 mapping. Failure -> cause: 7.3b interface present = network mode; 7.3c writable `/var/tmp` = no `--read-only` (non-root alone does not fix it); 7.3d uncapped `/tmp`; 7.3e no `--pids-limit`; 7.3f hog reaches ~2x the cap = `--memory-swap` missing (or no cap at all); 7.3g uid/CapEff/NoNewPrivs; 7.3h SIGTERM-ignoring job survives = only the inner `timeout`; leaked `sbx-*` = no trap/janitor, `--rm` alone is not enough when the client is killed. 7.3i is the control with an open air-gap network (the tripwire sees the probe's DNS query): it proves 7.3b measures the learner's `--network`.
- **7.4** (a-f): argv list to the runner, temp file (mode 644), clamp `timeout_s` to 1..30, truncate to 64 KiB, JSON string result, never `shell=True`. Common: trusting `timeout_s=600`, `subprocess.run(..., shell=True)`, file mode 600 (container user cannot read it), returning a Python dict instead of the documented JSON string, leaving containers behind on timeout.
- **7.5** (a-f): dimension taken from the first embedding response (384, not hard-coded), `Cosine`, deterministic ids (`uuid5` of `source:chunk_index`), batched embedding input, `?wait=true`, chunking by `re.split(r"\n\s*\n")` + strip, only `.md/.txt`, query embedded with the same alias, `points/query` for search. Common: random ids (duplicates on re-run), `split("\n\n")` (misses the whitespace-only line), ingesting `.json`, one request per chunk, vectors not normalised issue is not applicable (Cosine).
- **T**: remove `--privileged`, the docker.sock mount and the `/etc` mount (`:ro` only prevents writes, `shadow`/keys stay readable); keep the job-dir mount read-only and the benign job working. Grader finds the live container and checks `Mounts` and `HostConfig.Privileged`, plus a probe reading `/proc/self/mountinfo` and the socket path from inside. Common: only adding `:ro`, deleting the runner, removing the mounts but leaving `--privileged`.
- 7.6 (unscored): new collection with the new dimension, re-embed, `POST /collections/aliases` with delete+create in one request; repointing only the gateway alias breaks ingest (400 dimension mismatch) and silently degrades queries against the old collection.
