## 4 vLLM CPU — WORKS-WITH-CAVEAT (use v0.31.0 + float32; NOT v0.32.0, NOT float16)
- v0.32.0 (`--dtype float16` as in plan, default flags): engine init OK, then hangs >18 min in "Warming up model for the compilation" (3 cores at 100%, never reached healthy). With `--enforce-eager --max-num-batched-tokens 512` it starts in <90 s but **the first request kills the engine: `RuntimeError: Boolean value of Tensor with more than one value is ambiguous`** at `vllm/utils/cpu_triton_utils.py::_compute_slot_mapping_kernel_impl` (`assert block_size * BLOCKS_PER_KV_BLOCK == KV_CACHE_BLOCK_SIZE`, kwargs mis-bound by `triton_utils/dispatcher.py::_launch`) -> HTTP 500 `EngineCore encountered an issue`. Same with float32. A v0.32.0 CPU bug on this host; logs `vllm-run{1,2,3}.log`.
- v0.31.0 + `--dtype float16`: eager mode starts but a single 36-token request ran >5 min at 300% CPU (fp16 matmul path unusable on N1). Plan's `--dtype float16` advice is wrong for N1.
- **v0.31.0 + `--dtype float32` WORKS**: flags `--model Qwen/Qwen2.5-0.5B-Instruct --dtype float32 --max-model-len 2048 --max-num-seqs 4`, `-e VLLM_CPU_KVCACHE_SPACE=1` (int GiB only; `0.25` -> pydantic int() error), `--security-opt seccomp=unconfined --cap-add SYS_NICE --shm-size 4g`. Default (compiled) mode: healthy ≈ 3-4 min (warm compile cache; engine init 79 s incl 13.6 s profiling); with `--enforce-eager --max-num-batched-tokens 512` healthy in <100 s. Gen ≈ 11.5 tok/s (compiled) / 9 tok/s (eager), 64 tokens in 5.6 s, TTFT ≈ 0.3 s on 37-token prompt. **RSS 5.9-6.4 GiB** (Worker 4.7 GB) — by far the heaviest component; run it alone (<8 GB cap ok, but nothing else big beside it). Model weights downloaded from HF inside the container (HF_HOME bind mount) — need internet or pre-seeded cache.
- KV 1 GiB fp32 = 43,520 tokens (24 layers x 2 x 2 kv-heads x 64 x 4 B = 24,576 B/token). Exact error when max-model-len too big (EngineCore ValueError, container exits 1): `To serve at least one request with the model's max seq len (65536), (1.5 GiB KV cache is needed, which is larger than the available KV cache memory (1.0 GiB). Based on the available memory, the estimated maximum model length is 43520. Try increasing `gpu_memory_utilization` (which also controls CPU memory on the CPU backend) or decreasing `max_model_len` when initializing the engine. See https://docs.vllm.ai/en/latest/configuration/conserving_memory/ for more details.` (65536 needs `VLLM_ALLOW_LONG_MAX_MODEL_LEN=1` since Qwen max is 32768.)

## 5 LiteLLM v1.106.4 + pgvector pg17 + Valkey 9 — WORKS-WITH-CAVEATS (fake backend: ~40-line stdlib server; harness uses `.build/spike/gw/` files)
- Startup ≈ 25-40 s incl. prisma migrate (213 migrations). `/key/generate` with models, rpm_limit 2, tpm_limit OK. Valkey 9 accepted by LiteLLM (redis protocol) — compat confirmed.
- **Backend `id` caveat (affects the mock design):** LiteLLM uses the backend response `id` as `request_id` (primary key of SpendLogs). A constant id (`c1`) made every success row after the first silently vanish (key spend still updated, `LiteLLM_SpendLogs` empty). mock-vllm MUST return a unique id per response.
- Burst: 200 requests (8 threads) against rpm_limit 2 -> **{200: 2, 429: 198}**; 429 body `Rate limit exceeded for api_key: <hash>. Limit type: requests. Current limit: 2, Remaining: 0. Limit resets at: <ts>`; headers `retry-after: 60`, `rate_limit_type`, `reset_at`, `x-ratelimit-api_key-{limit,remaining}-{requests,tokens}`. **Recovery: fixed window, 60 s** (polled every 5 s: 429 until 60 s, then 200). tpm_limit 50: 2 requests pass (30 tokens each, post-hoc counted), then 429 `Limit type: tokens`. Wrong model for key -> 403 `key_model_access_denied`.
- Budget (max_budget 0.1, model_info cost 0.001/token, 30 tok/req = 0.03): sequential 1/s -> 4 x 200 then **HTTP 422** `Budget has been exceeded! Key=… Current cost: 0.12, Max budget: 0.1` (status 422 with `type:"budget_exceeded"`, not 400/429; allows one overshoot request). Enforcement uses the in-memory spend and is immediate (no batch lag) on a single replica; spend in DB lags ≤ proxy_batch_write_at. Under 8-way parallel burst the logged "Current cost" values were erratic (e.g. 32.8, 65.7): grade budgets with SEQUENTIAL requests only.
- Spend-log lag with `proxy_batch_write_at: 5` (after fixing unique ids; 6 trials): row visible in `LiteLLM_SpendLogs` after **2.1-5.4 s** (≈ 2-5 s). Failed (429/422) requests are also logged (status=failure, spend 0). `/spend/logs?request_id=` returned `[]` even for existing rows in one probe (use `/spend/logs?start_date=…&end_date=…` or psql); `/key/info` spend is correct.
- Prometheus: `callbacks: ["prometheus"]` works with the free image (no enterprise licence). `/metrics` 307-redirects to `/metrics/`; **requires master key (401 without)**; `litellm_settings: require_auth_for_metrics_endpoint: false` (under litellm_settings, NOT general_settings) makes `/metrics/` open. Metric names (litellm_ prefix): `proxy_total_requests_metric_total, proxy_failed_requests_metric_total, requests_metric_total, spend_metric_total, input_tokens_metric_total, output_tokens_metric_total, total_tokens_metric_total, remaining_api_key_budget_metric, remaining_api_key_requests_for_model, remaining_api_key_tokens_for_model, api_key_rate_limit_allowed_metric/used_metric, request_total_latency_metric_*, llm_api_latency_metric_*, overhead_latency_metric_*, request_queue_time_seconds_*, deployment_{state,success_responses_total,failure_responses_total,latency_per_output_token_*}, in_flight_requests, llm_api_failed_requests_metric_total, redis_circuit_breaker_state, active_users/teams_count`. Labels incl. `hashed_api_key, api_key_alias, requested_model, model, model_id, team, user, client_ip, user_agent, route, exception_status`. **Scrape traffic itself shows up as failed requests when unauthenticated (route /metrics).**
- **Two replicas + Valkey global limit: only with `litellm_settings: cache: true` + `cache_params: {type: redis, host: valkey, port: 6379, supported_call_types: []}`** (empty list = no response caching). With only `router_settings.redis_*` each replica enforced rpm separately (4 requests passed on rpm=2; valkey empty). With cache params: rpm 2 -> replica A 200,200 then replica B 429 x3 (global). Keys appear in Valkey (`{api_key:<hash>}:requests|tokens|window`, `spend:key:<hash>`).
- RAM: litellm 0.56-0.77 GB each, pg 0.06, valkey 0.015, fake 0.02. 1 replica gateway ≈ 0.7-0.9 GB; 2 replicas ≈ 1.4 GB.

## 11 Tripwire (dnsmasq on `internal: true`) — WORKS
- Net `docker network create --internal --subnet 172.29.250.0/24`; sink container with static IP running `dnsmasq -k --no-resolv --no-hosts --log-queries --log-facility=- --address=/#/<sinkIP>` + python HTTP sink. Client with `--dns <sinkIP>`: `huggingface.co` -> sink IP, `GET http://huggingface.co/api/models/x` reached sink which logged `host=huggingface.co path=/api/models/x`; dnsmasq log shows `query[A] huggingface.co from <client>`; direct IP (1.1.1.1) -> `Network is unreachable`. Without the custom DNS the internal net gives `SERVFAIL` (no leak either way). Caveats: HTTPS never reaches the sink HTTP log (only the dnsmasq query log shows the Host: use the DNS log as the authoritative tripwire; AAAA gets REFUSED, harmless); containers on an internal-only network cannot publish ports to the host (access via a helper container on both nets). Works in compose too (`internal: true` network + `dns:` + static ipam).

## Surprises that change the plan
1. vLLM: pin v0.31.0, `--dtype float32` (NOT float16), `VLLM_CPU_KVCACHE_SPACE` int only; ~6 GB RAM; v0.32.0 CPU is broken (slot-mapping bug). Plan KV math labs: fp32 KV = 24,576 B/token for Qwen2.5-0.5B.
2. LiteLLM global rate limit across replicas needs `litellm_settings.cache` redis params; `router_settings.redis_*` alone does not share limits. Budget exceeded = HTTP 422. `/metrics` needs auth (or `litellm_settings.require_auth_for_metrics_endpoint:false`) and 307-redirects to `/metrics/`.
3. Mock backends must emit unique response `id`s or LiteLLM drops spend-log rows (pk collision).
4. llama.cpp Q8 prompt-eval ≈3x Q4_K_M on N1; gen speed noisy: redesign the quantization size lab around size/RSS/prompt-eval ratios with generous thresholds. `/metrics` has no KV gauge; `/slots` is minimal when idle.
5. Langfuse v4 is not usable with the cached ClickHouse 25.8; pin v3.
6. Docker 29 containerd store: `kind load docker-image` fails (use `docker save --platform linux/arm64 | kind load image-archive`); registry digests differ from local ones.
7. aider-chat conflicts with hub 2.3.0/openai 3.38 (separate venv). `hf download` needs repeated `--include`, and downloads multi-GB onnx by default.
8. fake-gpu-operator works on arm64 kind but its DCGM exporter only has FB_USED/FB_FREE/GPU_UTIL: keep mock-dcgm for the rest.
9. Image sizes: seaweedfs 699 MB, open-webui 5.8 GB, vllm 4.5 GB (not the compressed figures in the plan).
10. Tripwire: only the DNS log sees HTTPS hosts. Internal-network containers can't publish ports.
11. Lock-discipline gap in this spike (see top); whole-course harness must acquire the flock itself.
