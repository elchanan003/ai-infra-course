# 06 — Tutor answers

## Quiz
1. Many Open WebUI settings (connections, RAG engine, feature flags) are PersistentConfig: the env var is read on FIRST boot only and stored in the DB; later boots use the stored value. Fix: change it through the admin UI/API (`POST /openai/config/update`), recreate the data volume (fresh state), or set `ENABLE_PERSISTENT_CONFIG=false` so env always wins (UI edits no longer persist).
2. Chat title generation, tag generation, follow-up suggestions, input autocomplete, search/RAG query generation, embeddings for RAG (to `embed`). Reduce: set the task model to a small alias (`TASK_MODEL_EXTERNAL`), disable features not needed, rate-limit the key, and measure requests per user message.
3. Master key = full admin (create keys, read spend), a leak is catastrophic; a developer's key couples the UI to a person (revoked when they leave) and mixes spend. Dedicated key `owui-prod`: models only `chat`/`chat-small`/`embed`, RPM sized for users, team budget, metadata owner; rotatable independently.
4. Chat: `/v1/chat/completions`, instruct model, role messages + chat template, long streamed output, TTFT ~1-2 s, per human message. FIM: `/v1/completions` (or llama.cpp `/infill`), base coder model (often 1.5-7B), prefix+suffix with model-specific FIM tokens, 32-128 token output, whole suggestion in ~100-400 ms, per typing pause (very high QPS). Own alias+key: different model, very different limits, SLO, and isolation from agents/chat.
5. `<|fim_prefix|>def add(a, b):\n    <|fim_suffix|>\n\nprint(add(1, 2))<|fim_middle|>` (model generates the middle, e.g. `return a + b`). To a chat-tuned model via chat completions: it does not know the tokens as a task; it treats them as text, answers conversationally or rambles; no error is raised (silent quality failure).
6. High QPS: separate key with high RPM and small TPM/`max_tokens`; client cancels on keystroke -> connection aborts must be propagated to the engine; small fast model with SLO (latency beats quality); prefix caching helps (shared prefix between consecutive requests); keep it out of the agent pool.
7. Each `models:` entry has its own `apiBase`, `apiKey`, `model` and `roles`: chat entry (roles chat/edit/apply) with the chat key limited to `chat`; autocomplete entry with the FIM key limited to `coder`. Least privilege: a leaked autocomplete key cannot run chat or other models; limits tuned per role; spend attributable per role.
8. System prompt with edit-format rules, repo map (tree-sitter summary), contents of files in chat, history, user message. Large because files and repo map are resent every turn. `whole`: model rewrites the whole file: more robust for weak models, but many more output tokens and slower/costlier; `diff` (SEARCH/REPLACE) is compact but requires exact matches.
9. Provider/protocol prefix: use `openai/chat` (the `openai/` prefix tells Aider's LiteLLM layer to speak the OpenAI protocol to the base URL); also check the base URL includes `/v1`, and the key.
10. Sum = nP + d*n(n+1)/2 = 30*12 000 + 1 500*465 = 360 000 + 697 500 = 1 057 500 prompt tokens; distinct information ~ P + n*d = 57 000. With a prefix cache the engine mostly prefills only the new tokens each turn: ~57 000 vs ~1.06 M, roughly 18x less prefill (about an order of magnitude).
11. `tools`: JSON-schema descriptions of functions the model may call; `tool_choice`: auto/none/forced function; `tool` role messages: results of executed calls, linked by `tool_call_id`, appended to history. Failure reasons: engine started without tool-call parsing (vLLM `--enable-auto-tool-choice` + `--tool-call-parser`), model not tool-capable or emits malformed JSON, gateway group/provider that does not pass `tools`, proxy dropping SSE tool-call deltas, chat template without tool support.
12. `User-Agent` header (and client-set headers), model alias/endpoint (`/v1/completions` with suffix = FIM), key alias/team, request shape (huge system prompt + `tools` = agent; repo-map style prompt = Aider), prompt-size/rate pattern. (Prometheus metric label `user_agent`.)
13. Buffering turns streaming into a single late response: UX/timeouts break and TTFT is lost; tool-call deltas must arrive incrementally. Once the first bytes are sent the status is already 200: retries/fallbacks cannot restart, the client sees a truncated stream and must retry itself.
14. Hypotheses: agents saturate the shared engine (KV/queue), so FIM waits; the autocomplete shares a pool/alias with agents or its model is large. Check: engine queue/KV metrics, per-key request rates and `max_parallel_requests`, alias->deployment map. Fixes: separate `coder` alias/pool, `max_parallel_requests`/TPM on agent keys, prefix caching, smaller FIM model.
15. (a) A stale Ollama URL stored in the DB with `ENABLE_OLLAMA_API` true (Open WebUI waits for the timeout); (b) the OpenAI connection missing/pointing at an old gateway address. Fix in the stored config via admin UI/API (`/ollama/config`, `/openai/config/update`), not just compose env (PersistentConfig).

## Lab — expected answers
- 6.1 key `lab-owui` models [chat, embed]; connect.sh: `POST /api/v1/auths/signin` (token) then `POST /openai/config/update` with `OPENAI_API_BASE_URLS=["http://litellm:4000/v1"]` (container-network name, not localhost), `OPENAI_API_KEYS=[KEY_OWUI]`, `ENABLE_OPENAI_API=true`; `POST /ollama/config/update` with `ENABLE_OLLAMA_API=false`.
- 6.2 `OPENAI_API_BASE=http://127.0.0.1:18040/v1`, `OPENAI_API_KEY=$KEY_AIDER`, `--model openai/agent`, `--no-analytics --no-check-update --no-show-model-warnings --yes-always --no-auto-commits (optional) --message "..."`; format used by the scripted reply: SEARCH/REPLACE (diff).
- 6.3 chat model `provider: openai, model: chat`, roles chat/edit/apply with chat key; autocomplete `model: coder`, role autocomplete, FIM key, `defaultCompletionOptions.maxTokens` small. FIM request echo shows `prompt` (prefix) and `suffix` (or FIM tokens). FIM key on chat = 403.
- 6.4 values are per-learner; method: `jq '.messages[0].content|length'`, `.tools|length`, `.messages|length`, count of `role=="tool"`; logged tokens from spend log (`/spend/logs` or psql `LiteLLM_SpendLogs.prompt_tokens`); session total = n*P + d*n(n+1)/2 with P from system+tools tokens (chars/ratio) and d from per-turn growth; savings = total - (P + n*d).
- 6.5 `GET /ollama/config` shows `ENABLE_OLLAMA_API: true` + stale `OLLAMA_BASE_URLS`; fix: `POST /ollama/config/update` `{ENABLE_OLLAMA_API:false,...}` and set the OpenAI connection (6.1 again, since the plant removed it); persisted in DB so it survives restarts.

## Common mistakes
- Using `http://localhost:18040/v1` inside the Open WebUI container (localhost is the container itself) — use the compose service name.
- Editing compose env and restarting (PersistentConfig).
- Aider model `chat` without `openai/`; missing `/v1`; leaving analytics/update checks on (outside hosts hit the tripwire).
- Continue autocomplete pointed at the `chat` alias (chat model on completions) or using one key for both roles (6.3.4 fails).
- 6.4: counting characters of the whole JSON instead of the system message; mixing tool schemas into the system prompt count; using tokens from a different request.
- 6.5: fixing only the Ollama flag but leaving the gateway connection missing (list empty), or fixing via env only.
